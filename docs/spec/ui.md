# UI 仕様 — 画面構成とデザインシステム

セッション画面 (`/s/{id}` 以下) の **画面構成・ナビゲーション・共通部品・見た目の決まりごと** を定める。
各画面に「何を出すか (データ)」は [`combat-stats.md`](./combat-stats.md) と [`run-overview.md`](./run-overview.md) に従う。
ここに無い見た目・部品は使わない。足すときは先にこの文書を直す (CLAUDE.md §3.2)。

2026-10-03 確定事項: 3 タブ構成 (ラン全体 / 階 / 戦闘)、部品は自前 (Tailwind)、今の暗い配色を磨く、スマホでも読める程度に対応。
ラン全体と階の詳細は別の画面にする。ラン全体にはプレイヤーごとのデッキ・レリック・ゴールド・バッジを出す (同日確定)。

---

## 1. 画面と URL

画面の状態 (どの画面・どの戦闘・どの階・どのプレイヤー) は **すべて URL に持つ**。リンクで共有でき、ブラウザの戻る / 進むが効く。

| 画面 | URL | 内容 |
|---|---|---|
| ラン全体 | `/s/{id}` | HP 推移 (全員)、プレイヤーごとのカード (デッキ・レリック・ポーション・ゴールド・バッジ) |
| 階の一覧 | `/s/{id}/floors` | 全階の表。行を選ぶと詳細へ |
| 階の詳細 | `/s/{id}/floors/{floor}` | 1 階分の詳細 (run-overview.md §2.4) |
| 戦闘 | `/s/{id}/combats` | 全戦闘の合計 (主要数値・プレイヤー比較・貢献スコア・カード別・デバフ) |
| 戦闘詳細 | `/s/{id}/combats/{combat_index}` (`?view=summary\|turns\|timeline`) | 1 戦闘の統計 |

- 全画面共通のクエリ `?p={player_id}` = 選んでいるプレイヤー。画面を移っても引き継ぐ。無ければ `doc.players` の先頭。
- 知らない URL・存在しない戦闘や階は、それぞれラン全体・戦闘・階の一覧に戻す (エラー画面にしない)。
- 画面内の操作で状態が変わったら URL を更新する。画面の切り替え・戦闘の選択は履歴に積む (`pushState`)、
  プレイヤー・表示の切り替えは置き換える (`replaceState`)。
- backend は `/s/{id}` と `/s/{id}/*` の両方で同じ `index.html` を返す。

## 2. 画面の骨格 (AppShell)

```
┌ ヘッダー ──────────────────────────────────────────────┐
│ 参加者名 (vd・agapants・0407yuuku)             ● 完了 │
│ [3 人] [アセンション 4] [45 階] [勝利]      最終更新 … │
├ ナビゲーション ─────────────────────────────────────────┤
│ ラン全体 │ 階 │ 戦闘                    プレイヤー: [● vd ▾] │
├────────────────────────────────────────────────────────┤
│ 画面の本文 (最大幅 1280px、左右 16px 以上の余白)           │
└────────────────────────────────────────────────────────┘
```

- **ヘッダー**: 参加者の表示名 (見出し)、バッジ (1 人ならキャラクター名・複数ならプレイ人数、アセンション、最終階、結果)、ライブ状態 (ライブ / 完了 / オフライン) と最終更新。
- **ナビゲーション**: 3 つのタブ (リンク)。今の画面に `aria-current="page"`。
- **プレイヤー切り替え**: プレイヤーが 2 人以上のときだけ、ナビゲーションの右に 1 つだけ置く。各プレイヤーの固定色の丸を付ける。
  画面ごとにプレイヤーのボタンを置かない。
- 狭い画面 (640px 未満): タブは横スクロール、プレイヤー切り替えはセレクトボックス。

## 3. 各画面

### 3.1 ラン全体

ランの結果・到達階はヘッダーのバッジで示し、本文に数値のタイルは置かない (2026-10-03 確定)。

1. **HP 推移** (全員): 全幅のグラフ。プレイヤーごとの線をプレイヤー色で重ねる (1 人なら 1 本)。点を押すとその階の詳細へ。
2. **プレイヤーごとのカード** (全員。広い画面では横に並べ、狭い画面では縦に並べる)。各カード:
   - 名前・キャラクター・最終 HP / 最大 HP・ゴールド
   - **バッジ** (ラン終了時にゲームが判定するもの。ラン中は「ラン終了後に表示」、`run_end` に記録が無い古いセッションは「記録がありません」。色は銅 / 銀 / 金、ホバーで説明)
   - **レリック** (チップ)・**ポーション** (チップ)
   - **デッキ** (最後の階の時点。種類ごと (アタック / スキル / パワー / その他) にまとめ、同じカードは「×N」でまとめる。チップは run-overview.md §2.5)
   - プレイヤー切り替えで選んでいる人のカードは枠を強調する

### 3.2 階の一覧

1. **階の表**: 階・部屋 (バッジ)・遭遇 / イベント名・HP (退出時と増減)・ゴールド (退出時と増減)・主な変化 (入手・購入・強化・除去を 3 件まで + 「ほか N」)。
   選んだプレイヤーの視点。行全体が階の詳細へのリンク。

### 3.3 階の詳細

1. パンくず「階 › 12 階」と、前の階 / 次の階へのリンク。
2. 見出し: 部屋の種類・遭遇 / イベント名。戦闘の階は「この戦闘の詳細へ」(戦闘詳細へのリンク)。
3. HP・ゴールド (退出時、入場時と増減) のタイル。
4. 内容は run-overview.md §2.4 (入手、デッキ改造、ショップ購入、選択)。選んだプレイヤーの視点。

### 3.4 戦闘

戦闘の選択は **ドロップダウン (戦闘セレクタ)** で行う (2026-10-03 確定。一覧の表は置かない)。
戦闘・戦闘詳細の両方の画面の上部に同じものを置き、選ぶと URL が変わる (`/combats` ⇔ `/combats/{n}`、履歴に積む)。
- 選択肢: 「全戦闘の合計 (N 戦)」+ 各戦闘「{順番}. {遭遇名}」(エリート・ボスは「[エリート]」「[ボス]」を付ける)
- 横に「‹ 前」「次 ›」のボタン (戦闘詳細のときだけ有効)

1. 戦闘セレクタ。
2. **全戦闘の合計**: 主要数値 (選んだプレイヤー。大: 有効与ダメージ・被ダメージ・有効ブロック・与ダメ貢献 (rDPS)・被ダメ軽減貢献 (rMit)、
   小: 与ダメージ HP・オーバーキル・総獲得ブロック・味方付与ブロック・エナジー・カード使用枚数・ポーション・最大カードダメージ)、
   プレイヤー比較 (全員。プレイヤーを行にした表、各列に横棒。1 人なら出さない)、貢献スコア (全員)、カード別・デバフ付与 (選んだプレイヤー。カード別は上位 10 件 + 「すべて表示」)。

### 3.5 戦闘詳細

1. 戦闘セレクタ (§3.4)。
2. メタ情報: 遭遇名・部屋・結果・階・ターン数 (combat-stats.md §3.1) と「この階の詳細へ」(階の詳細へのリンク)。
3. 表示の切り替え (セグメント): **サマリ** / **ターン** / **タイムライン**。
   - サマリ: 主要数値 (選んだプレイヤー)、プレイヤー比較 (全員)、貢献スコア (全員、この戦闘)、カード別・デバフ付与 (選んだプレイヤー)。
   - ターン: ターン推移の表とグラフ (combat-stats.md §3.2)。
   - タイムライン: 既存のタイムライン。

## 4. デザインシステム

### 4.1 トークン

| 種類 | 値 |
|---|---|
| 背景の段階 | `bg-0` 画面 `#0b0d10` / `bg-1` パネル `#13161b` / `bg-2` パネル内の要素 `#1b1f26` / `bg-3` 境界線・押下 `#252a33` |
| 文字 | 主 `slate-100`、本文 `slate-200`、補助 `slate-400`、控えめ `slate-500` |
| 強調色 | `accent` `#7aa2f7` (選択中・リンク・フォーカス) |
| 意味の色 | 成功 `ok` `#9ece6a` / 危険 `bad` `#f7768e` / 注意 `warn` `#e0af68` |
| プレイヤー色 | `doc.players` の順に固定: `#7aa2f7` `#bb9af7` `#9ece6a` `#e0af68` `#f7768e`。グラフ・比較表・プレイヤー切り替えで同じ色 |
| 部屋の色 | run-overview.md §2.2 の `ROOM_TYPE_VISUAL` |
| カードの色 | run-overview.md §2.5 (レアリティ・強化) |
| 文字サイズ | 12 (注記) / 14 (本文・表) / 16 (パネル見出し) / 20 (画面見出し) / 28 (主要数値) |
| 余白 | 4px 刻み。パネル内 16px、パネル間 16px、セクション間 24px |
| 角丸 | 部品 6px、パネル 8px |

数値は等幅数字 (`tabular-nums`)、表の数値列は右寄せ。

### 4.2 共通部品

| 部品 | 使いどころ | 決まり |
|---|---|---|
| `Panel` | 画面の区切り | 見出し (範囲を明記: 「(全員)」または選んだプレイヤー名)・説明 (`InfoTip`)・右上の操作 |
| `StatTile` | 数値 | `primary` (大) と `secondary` (小)。ラベル・値・補足・説明 |
| `DataTable` | 一覧・集計 | 見出し行固定、数値は右寄せ、並べ替え可、行リンク可、件数が多いときは上位 N 件 + 「すべて表示」 |
| `Badge` | 状態・種類 | 結果 (勝利 / 敗北 / 進行中)、部屋の種類、アセンション等。色だけでなく文字でも示す |
| `Chip` | カード・レリック等 | run-overview.md §2.5 のまま |
| `InfoTip` | 説明 | 「?」ボタン。**押す (タップ) と開く** ポップアップ。マウスを乗せたときも開く。Esc / 外を押すと閉じる |
| `SegmentedControl` | 同じ画面内の表示の切り替え | 2〜4 個。画面の移動には使わない |
| `NavTabs` | 画面の移動 | リンク (`<a>`)。今の画面に `aria-current` |
| `PlayerSwitcher` | プレイヤーの選択 | AppShell に 1 つだけ |
| `EmptyState` | データが無いとき | 何が無いのか + 次にすること (1 行) |
| `Skeleton` | 読み込み中 | 画面の骨格の形 |

### 4.3 使い分けの決まり

- **画面の移動はリンク**、**画面内の表示の切り替えはセグメント**、**プレイヤーの選択は AppShell の 1 か所**。戦闘の選択は例外的にドロップダウン (§3.4)。
- 1 つのパネルの中で、選んだプレイヤーの数値と全員の数値を混ぜない。パネル見出しに範囲を書く。
- 表示の言葉は日本語に揃える: カードの種類 (アタック / スキル / パワー / 状態異常 / 呪い)、パワー名はゲーム内の表示名、
  貢献スコアは「与ダメ貢献 (rDPS)」「被ダメ軽減貢献 (rMit)」。英語のまま出すのは固有の略語だけ。
- 操作できるものは `button` か `a`。キーボードで操作でき、フォーカスが見える (`accent` の枠)。

### 4.4 狭い画面 (スマホ)

- 640px 未満: 1 列に並べる。数値タイルは 2 列。表は横スクロール (ページ全体は横にスクロールさせない)。
- 1024px 以上: ラン全体のプレイヤーのカードを横に並べる (最大 3 列)。
